# Spec: order-service (`:8081`) — REST in, Kafka out

## ADDED Requirements

### Requirement: Accept an order over REST
The `order-service` SHALL accept `POST /orders` with body `{"customerId": <string>, "items": [{"sku","qty","price"}…]}`
and SHALL generate the `orderId` itself (UUID), ignoring any client-supplied `orderId`.

#### Scenario: valid order accepted
- **WHEN** a client posts a valid order
- **THEN** the service MUST respond `201 Created` with body `{"orderId","lineCount","kafkaKey","topic":"order-created"}`
- **AND THEN** `orderId` MUST be a UUID generated by the service
- **AND IF** the request body already carries an `orderId`
- **THEN** the response MUST carry the service-generated UUID and the client value MUST be ignored

### Requirement: One event per line item
The order-service SHALL publish one message per item, with `lineIndex` 0-based and contiguous.

#### Scenario: order of two items
- **WHEN** an order with items `A` and `B` is accepted
- **THEN** exactly 2 messages MUST appear on `order-created`, with `lineIndex` 0 and 1, all sharing the same `orderId` key

### Requirement: Validation before publication
The order-service SHALL validate the request before touching Kafka and SHALL respond `422 Unprocessable Entity`
with body `{"errors":[{"field","reason"}…]}` and publish nothing.

#### Scenario: empty item list
- **WHEN** `items` is an empty array
- **THEN** the response MUST be `422` with an error for `items`
- **AND THEN** no message MUST be published to `order-created`

#### Scenario: invalid numeric fields
- **WHEN** an item has `qty <= 0` or `price < 0`
- **THEN** the response MUST be `422` naming the offending index, e.g. `items[0].qty`
- **AND THEN** no message MUST be published

#### Scenario: oversized or blank strings
- **WHEN** `sku` or `customerId` is blank or longer than 200 characters
- **THEN** the response MUST be `422` naming that field

#### Scenario: too many items
- **WHEN** `items` has more than 100 entries
- **THEN** the response MUST be `422` with reason `too many items`

#### Scenario: malformed JSON body
- **WHEN** the request body is not valid JSON
- **THEN** the service MUST respond `422` (not a 500 stack trace) and publish nothing

### Requirement: Demo navigation surface
The order-service SHALL expose `GET /orders` returning the orders it accepted during this run
(`orderId` + `lineCount`) and `GET /health`.

#### Scenario: nothing accepted yet
- **WHEN** no order has been posted since start
- **THEN** `GET /orders` MUST return `200 []`

### Requirement: Broker lifecycle
The order-service SHALL keep exactly one `KafkaTemplate` for its lifetime and SHALL destroy it on shutdown.

#### Scenario: graceful shutdown
- **WHEN** the service receives a stop signal (SIGINT)
- **THEN** it MUST unsubscribe its beans, call `KafkaTemplate.destroy()`, and log the number of buffered/pending messages
